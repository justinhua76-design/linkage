# PRODUCT_SPEC — uSciTec BioAge AI（MVP / Sprint 1）

## 1. 产品定位

不依赖 DNA 甲基化、基于常规血液检测的生物年龄与健康管理系统。Sprint 1 交付的是**研究与内部验证版本**，核心是一个确定性、可追溯、经过测试的 Levine 2018 Clinical PhenoAge 计算引擎，以及配套的最小数据管理界面。

### 范围外（明确不做）

* 疾病诊断、风险分层建议、治疗或干预建议；
* 用大语言模型或任何非确定性方法生成或修改年龄数值；
* 真实患者的身份信息管理：只保存研究编号（假名），不保存姓名、证件号或联系方式。

## 2. 用户与角色

| 角色 | 典型用户 | 能做什么 |
|---|---|---|
| clinician | 研究医生、研究护士 | 新建受试者、录入指标、计算并保存结果 |
| researcher | 数据分析人员 | 查看数据、做临时计算（不保存） |
| viewer | 监查员 | 只读 |
| admin | 系统管理员 | 全部权限，可查看审计日志 |

## 3. 功能（Sprint 1）

| # | 功能 | 验收标准 |
|---|---|---|
| F1 | PhenoAge 计算引擎 | 九项指标加实际年龄返回 PhenoAge；与独立参考实现的差 < 1e-6 岁 |
| F2 | 标准化检测数据模型 | 每条记录保存原始值和原始单位、模型单位值、检测日期、来源、参考范围（及其来源）、检出限信息和质量状态 |
| F3 | 严格校验 | 单位错误、缺失、非法值、CRP 为 0 或检出限信息不完整时，返回 422 和逐项原因，绝不返回年龄 |
| F4 | `POST /api/v1/bioage/phenoage` | 见 `API_SPEC.md` |
| F5 | 页面：新建患者 | 研究编号格式校验，提示禁止填写可识别信息，可标记"合成数据" |
| F6 | 页面：手工录入指标 | 9 项指标各配单位下拉；CRP 支持"低于检出限"和检出限；可根据出生日期自动计算实际年龄；服务端错误逐项显示在对应字段旁 |
| F7 | 页面：计算结果 | 显示 PhenoAge、实际年龄、差值、警告、逐项单位换算，以及模型版本、计算时间、系数指纹和算法来源 |
| F8 | 页面：指标概览 | 9 项指标的最新值、参考范围、来源、质量状态，以及计算历史 |
| F9 | 安全与合规基础 | 基于角色的权限控制、审计日志、密钥只来自环境变量、应用日志中不出现患者数据 |
| F10 | 文档 | 本文件、`CLINICAL_MODEL.md`、`API_SPEC.md`、`VALIDATION_PLAN.md` |

## 4. 非功能需求

* **确定性**：相同输入始终得到相同输出；常数通过 SHA-256 指纹锁定。
* **可追溯**：每条结果保存模型 ID 和版本、引擎版本、系数指纹、算法来源、计算时间、计算者、LOD 策略、全部输入（原始值与模型值）以及所用检测记录的 ID。
* **数据最小化**：只用假名编号；出生日期可选。
* **日志**：JSON 结构化日志，只记录请求 ID、路由模板、状态码、耗时和资源 ID。另有一道过滤器兜底：删除不在白名单内的 extra 字段，并把日志消息中的数字一律替换成 `[redacted]`。SQLAlchemy 参数日志已关闭，uvicorn 自带的访问日志也已禁用。
* **密钥**：只来自环境变量 / `.env`（已加入 `.gitignore`），仓库只提供 `.env.example`。前端访问后端的令牌只保存在 Next.js 服务端，浏览器通过同源代理访问 API，拿不到令牌。

## 5. 架构

```
浏览器 ──► Next.js (App Router, TS)
           ├─ 服务端组件：通过 BACKEND_API_TOKEN 读取数据
           └─ /api/backend/* 同源代理（路径白名单）
                      │
                      ▼
           FastAPI（Python）
           ├─ api/v1       路由、角色权限、审计
           ├─ services     编排、溯源
           ├─ domain       单位 / 校验 / PhenoAge（纯函数、确定性）
           └─ db           SQLAlchemy 2 + Alembic
                      │
                      ▼
           PostgreSQL 16
```

## 6. 后续 Sprint 候选

1. 认证改为 OIDC 或 SSO，并接入组织内的用户目录；
2. 实验室数据导入（HL7 v2 / FHIR Observation / CSV），按 LOINC 映射指标；
3. 用 NHANES 公开数据做批量验证，并评估中国人群的校准（见 `VALIDATION_PLAN.md`）；
4. 纵向趋势展示，以及 PhenoAgeAccel（需要参考人群做回归）；
5. 其他确定性模型，如 KDM 生物年龄和 HD。
